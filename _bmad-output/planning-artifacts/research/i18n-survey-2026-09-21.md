# Khảo sát Đa ngôn ngữ (i18n) — Đại Ngàn Xanh
Ngày: 2026-09-21 · Phạm vi: UI + Email + Contract + DB content + Admin + Notifications + Tests

## 1. Stack hiện tại
- **FE**: Next.js 16 App Router + React 19 + Tailwind — `dainganxanh-landing/`
- **BE**: Supabase (Postgres + Edge Functions Deno) + Next.js API routes. KHÔNG có NestJS.
- **Email**: React Email (`src/emails/*.tsx`) render qua `@react-email/render` → Resend (`src/lib/email/mailer.ts`). + HTML inline trong Edge Functions.
- **Contract**: `docx-templates` fill `templates/contract-template.docx` → PDF (`src/app/api/contracts/generate/route.ts`).
- **i18n**: CHƯA có (không next-intl/i18next/useTranslation).

## 3. Middleware / routing hiện tại
- `src/middleware.ts`: **auth (Supabase getUser) + CSP/security headers gộp 1 hàm**, protect `/crm`, matcher loại static. → Thêm `[locale]` segment phải refactor cẩn thận (compose next-intl middleware với auth + giữ CSP).
- `next.config.js`: Sentry (`withSentryConfig`), `output: standalone`, remote images, CDN assetPrefix tùy chọn. i18n config mới phải wrap qua `createNextIntlPlugin`.
- Deploy: Dockerfile/nixpacks, domain production (Dokploy). Locale prefix `/vi`,`/en` ảnh hưởng SEO → cần hreflang + sitemap per-locale.

## 4. Quyết định kiến trúc cần chốt
| Quyết định | Khuyến nghị sơ bộ |
|---|---|
| Framework UI | `next-intl` (RSC-native, App Router + React 19, có `createNextIntlPlugin` + middleware) |
| Routing | Prefix `/vi` (default, không prefix) + `/en` — `localePrefix: 'as-needed'` |
| DB content | Bảng `*_translations` phụ (post_translations, product_translations…) hoặc JSONB `translations` — chốt theo số ngôn ngữ & SEO slug |
| Email | Render React Email theo `profiles.locale`; migrate Edge Fn inline HTML → shared templates |
| Contract/cert | docx per-locale template + font Unicode cho certificate |
| Locale user | Thêm `users.locale` (`vi` default) + language switcher |
| Admin input | Form tab VI/EN trong BlogEditor & admin forms |
